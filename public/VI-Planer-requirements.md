# VI Planer — требования с нуля

Документ описывает бизнес-требования, use cases, функциональные и нефункциональные требования для создания приложения единого портфеля проектов и продуктов.

---

## 1. Продуктовая цель

Дать командам **единый портфель инициатив** (продукты + проекты) со сквозным приоритетом и расчётом сроков по реальной ёмкости команд, чтобы отвечать:

- «что делаем первым»;
- «когда закончим»;

без разрозненных бэклогов.

### Бизнес-цели (BR)

1. Единый сквозной приоритет между продуктами и проектами.
2. Честный ETA с учётом ёмкости и очередей нескольких команд.
3. Прозрачность кросс-командных инициатив и bottleneck.
4. Быстрый what-if по FTE/ёмкости без смены трекера.
5. Доступ по ссылке для команды без установки ПО.

### Out of scope (v1)

Auth/RBAC, аудит изменений, интеграция Jira/Linear, удаление команд, native mobile, realtime multiplayer, мультитенантность, approval workflow приоритета.

## 2. Акторы

| ID | Актор | Цель |
|---|---|---|
| A1 | Product / Portfolio Owner | Единый приоритет и ETA по всему портфелю |
| A2 | Team Lead | Очередь своей команды и загрузка ёмкости |
| A3 | Stakeholder / коллега | Просмотр плана и экспорт отчёта по ссылке |
| A4 | Администратор развёртывания | Опубликовать приложение и общую БД |

## 3. Use cases

### UC-01 — Просмотреть единый портфель

- **Акторы:** A1, A2, A3  
- **Триггер:** открытие приложения / вкладка «Портфель»  
- **Предусловия:** загружено состояние (облако / API / localStorage / демо)  
- **Основной сценарий:**
  1. Система показывает метрики: активные инициативы, горизонт, команды под риском, старт планирования.
  2. Система показывает таблицу инициатив (тип, команды, статус, WSJF, оценка, ETA).
  3. Пользователь может раскрыть «Адженда» с легендой колонок.
- **Альтернатива:** нет данных → заполнение демо-seed.  
- **Постусловие:** пользователь видит актуальный портфель.

### UC-02 — Отфильтровать и отсортировать портфель

- **Акторы:** A1, A2  
- **Триггер:** фильтр / клик по заголовку колонки  
- **Сценарий:** поиск, тип, команда, статус; сортировка по Приоритет / WSJF / Оценка / ETA; сброс фильтров.  
- **Постусловие:** таблица отражает выбранный срез.

### UC-03 — Создать инициативу

- **Актор:** A1  
- **Триггер:** «+ Инициатива»  
- **Сценарий:** заполнение полей (название, тип, бэклог, статус, владелец, WSJF, приоритет, заметки); назначение ≥1 команды с оценкой и стартом; live WSJF/ETA; сохранение.  
- **Альтернативы:** нет команд → alert; Отмена/Закрыть → без сохранения.  
- **Постусловие:** инициатива в портфеле, приоритеты уникальны 1…n.

### UC-04 — Редактировать / удалить инициативу

- **Актор:** A1  
- **Триггер:** клик по строке  
- **Сценарий:** изменение полей и команд → Сохранить.  
- **Альтернатива:** Удалить (без доп. confirm).  
- **Постусловие:** портфель и расписание пересчитаны.

### UC-05 — Изменить сквозной приоритет

- **Актор:** A1  
- **Триггер:** ввод ранга / drag ⋮⋮  
- **Предусловие drag:** сортировка по «Приоритет»  
- **Сценарий:** новый ранг; при конфликте — confirm; переиндексация 1…n; drag в видимом списке.  
- **Альтернативы:** drag при другой сортировке недоступен; отказ в confirm.  
- **Постусловие:** очереди и Gantt следуют новому порядку.

### UC-06 — Управлять командами и ёмкостью

- **Акторы:** A2, A1  
- **Триггер:** вкладка «Команды»  
- **Сценарий:** название, capacity 1–8 (шаг 0.5); создание команды; пересчёт ETA/риска.  
- **Альтернатива:** удаление команды — вне scope v1.

### UC-07 — Просмотреть очереди команд

- **Акторы:** A2, A1  
- **Триггер:** «Очереди команд» / «Очереди (тест)»  
- **Сценарий:** очередь по приоритету, план/сдвиг, даты, утилизация 8 нед.; в тест-режиме — «Может взять с…» и причина.

### UC-08 — Просмотреть сроки (Gantt)

- **Акторы:** A1, A3  
- **Триггер:** «Gantt/Сроки»  
- **Сценарий:** полоски по командам, bottleneck, зависимости очереди; горизонт 4–52 нед.  
- **Альтернатива:** статус «Готово» исключается из расписания.

### UC-09 — Сохранить и синхронизировать данные

- **Акторы:** A1, A2  
- **Триггер:** любое изменение  
- **Сценарий:** localStorage сразу; debounce → Supabase и/или PUT `/api/state`; индикатор синхронизации.  
- **Альтернатива:** API/облако недоступны → локальный fallback.

### UC-10 — Экспорт / импорт JSON

- **Акторы:** A1, A4  
- **Сценарий:** скачивание полного AppState; импорт с валидацией и уникальными приоритетами.  
- **Альтернатива:** неверный файл → ошибка.

### UC-11 — Скачать PDF текущей вкладки

- **Акторы:** A1, A3  
- **Сценарий:** цветной landscape A4 PDF метрик + активной вкладки.  
- **Альтернатива:** ошибка CDN-библиотек → alert.

### UC-12 — Сбросить к демо-данным

- **Актор:** A1  
- **Сценарий:** компактный confirm рядом с кнопкой; «Да» → seed + persist.  
- **Альтернатива:** Нет / Escape / клик снаружи.

### UC-13 — Открыть приложение по публичной ссылке

- **Акторы:** A3, A4  
- **Сценарий:** GitHub Pages / Render / LAN без установки.  
- **Альтернатива:** Pages без Supabase → данные per-browser.

## 4. Функциональные требования

| ID | Область | Требование |
|---|---|---|
| FR-01 | Портфель | Единый список продуктов и проектов с метками типа |
| FR-02 | Портфель | CRUD инициатив в модалке; валидация ≥1 команды |
| FR-03 | Портфель | Статусы: Идея / Готово к работе / В работе / Блокер / Готово |
| FR-04 | Приоритет | WSJF = (BV+TC+RO)/Job Size; поля 1–10 |
| FR-05 | Приоритет | Уникальный ручной Приоритет 1…n (1 = выше) |
| FR-06 | Портфель | Мультикомандные назначения: оценка + старт (понедельник) |
| FR-07 | Портфель | Фильтры: поиск, тип, команда, статус; сброс |
| FR-08 | Портфель | Сортировка: Приоритет, WSJF, Оценка, ETA |
| FR-09 | Приоритет | Drag-and-drop при сортировке по приоритету |
| FR-10 | Приоритет | Confirm при конфликте приоритета |
| FR-11 | Планирование | Расписание по ёмкости и порядку приоритета |
| FR-12 | Планирование | ETA = bottleneck (последняя команда по finish) |
| FR-13 | Очереди | Очереди команд + утилизация 8 недель |
| FR-14 | Очереди | «Очереди (тест)» с «Может взять с…» |
| FR-15 | Gantt | Полоски, bottleneck, зависимости очереди |
| FR-16 | Gantt | Горизонт 4–52 недели |
| FR-17 | Метрики | Активные, горизонт, риск команд, старт планирования |
| FR-18 | Метрики | Риск: спрос > capacity×8 |
| FR-19 | Команды | Название + capacity 1–8 шаг 0.5 |
| FR-20 | Команды | Создание команды с цветом и дефолтной ёмкостью |
| FR-21 | Данные | Persist: API → Supabase → localStorage → seed |
| FR-22 | Данные | Индикатор синхронизации в шапке |
| FR-23 | Обмен | Экспорт/импорт полного JSON |
| FR-24 | Обмен | Скачивание цветного PDF активной вкладки |
| FR-25 | Данные | Сброс к демо с обязательным confirm |
| FR-26 | Документация | Скачивание файла требований из UI (неявная кнопка внизу) |

## 5. Нефункциональные требования

| ID | Категория | Требование |
|---|---|---|
| NFR-01 | Производительность | Пересчёт портфеля ≤ 200 мс (~50 инициатив, ~10 команд) |
| NFR-02 | Производительность | Первая отрисовка UI ≤ 3 с |
| NFR-03 | Надёжность | localStorage сразу; remote debounce ≤ 500 мс |
| NFR-04 | Надёжность | При недоступности API/облака — локальный режим |
| NFR-05 | Доступность | Chrome/Edge/Safari last 2; desktop-first от 1280px |
| NFR-06 | Юзабилити | Деструктивный сброс демо — только с подтверждением |
| NFR-07 | Безопасность | v1: публичный shared store без auth (внутренний прототип) |
| NFR-08 | Безопасность | Валидация JSON на клиенте и сервере |
| NFR-09 | Совместимость | Относительные ассеты; base path для GitHub Pages |
| NFR-10 | Развёртывание | Local / Express / Pages±Supabase / Render |
| NFR-11 | Наблюдаемость | GET /api/health |
| NFR-12 | i18n | UI на русском (v1) |
| NFR-13 | Масштаб | До 200 инициатив, до 20 команд |
| NFR-14 | Офлайн | Работа из localStorage; PDF может требовать CDN |

## 6. Модель данных (v1)

### AppState
`version`, `startDate`, `teams[]`, `items[]`

### Team
`id`, `name`, `capacityPw`, `color`

### WorkItem
`id`, `title`, `type` (product|project), `backlog`, `status`, `owner`, `assignments[]`, `businessValue`, `timeCriticality`, `riskReduction`, `jobSize`, `notes?`, `manualRank`

### TeamAssignment
`teamId`, `estimatePw` (≥0.5), `workStartDate` (понедельник)

### Расчётные (не persist)
`ScheduledSlice`, `ItemSchedule` — очереди, ETA, bottleneck.

## 7. Критерии приёмки (smoke)

1. Создать инициативу на 2 команды.  
2. Изменить приоритет drag.  
3. Увидеть сдвиг ETA на Gantt.  
4. Экспорт JSON и PDF.  
5. Перезагрузить страницу — данные сохранились.  
6. Скачать файл требований из нижней кнопки.
