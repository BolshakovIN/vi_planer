Вердикт. VI Planer закрывает портфельное планирование ёмкости (RICE, сквозной приоритет, Gantt, очереди). Целевое ТЗ — управляемое изменение приоритетов в Jira/Structure с окном встречи, ролями и аудитом. Пересечение — таблица приоритетов и тип продукт/проект; платформа и governance — разные продукты.

2. Пробелы

Governance и сессии

  • «Открыть / закрыть сессию», snapshot
  • Yandex Calendar, тип «Планирование приоритетов»
  • Edit только в окне встречи
  • Глава PMO post-close + причина
  • История + обязательный комментарий → Jira

Роли и контуры

  • Viewer / PMO admin / product team
  • Запрет чужого контура
  • Режим «Проекты» | «Продукты» как раздельные ранги
  • Structure folders, домены PMO-tag
  • Справочники команд из Jira

Колонки таблицы

  • Код задачи (Jira key)
  • Первоначальная / актуальная даты
  • Дата создания; старт после ≠ new
  • ЧП и ROI (RUB, 12 мес.)
  • Editable на встрече: приоритет, дата, майка, статус

Платформа

  • Jira API / Forge / Structure sync
  • Auth / SSO / RBAC (сейчас публичный store)
  • Серверный запрет пустого приоритета и чужого контура

Стратегия: выбрать явно (A) эволюция SPA как planning twin, (B) новый Jira-модуль governance, (C) гибрид (чтение Jira, запись приоритетов только из сессии).

4. Бэклог доработок

Must

  1. Решение по архитектуре A/B/C
  2. Сессии планирования (open/close, read-only, snapshot)
  3. RBAC контуров (PMO ↔ Projects; PM ↔ свой Product)
  4. Обязательный комментарий + audit log
  5. Два независимых ранга + режим UI «Проекты» | «Продукты»

Should

  1. Yandex Calendar / keywords типа встречи
  2. Синхронизация с Jira (key, status, assignee, comments) — при A или C
  3. Колонки: key, даты, фильтр доменов
  4. Серверные запреты пустого приоритета и чужого контура
  5. Глава PMO post-close с формальной причиной

Could

  1. Поля ЧП / ROI (12 мес., RUB)
  2. Structure-like дерево / импорт folders
  3. Ретро-сравнение snapshots
  4. RICE/Gantt как аналитический слой рядом с meeting-priority

6. Рекомендация

Зафиксировать выбор A/B/C. Если цель — compliance приоритизации PMO: прототип сессии + RBAC + audit (даже на SPA), параллельно оценка Jira Forge/Structure. Не позиционировать текущий RICE/Gantt SPA как уже реализованный «Jira priority control».
