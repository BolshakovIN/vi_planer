# VI Planer — требования с нуля

Документ описывает бизнес-требования, use cases, функциональные и нефункциональные требования для создания приложения единого портфеля проектов и продуктов.

Актуально для текущего UI: вкладки **Портфель → Gantt/Сроки → Очередь команд → Настройки**; хранение GitHub Pages + Supabase (и опциональный API); PDF без CDN.

---

## 1. Продуктовая цель

Дать командам **единый портфель инициатив** (продукты + проекты) со сквозным приоритетом и расчётом сроков по реальной ёмкости команд, чтобы отвечать:

- «что делаем первым»;
- «когда закончим»;

без разрозненных бэклогов.

### Бизнес-цели (BR)

1. Единый сквозной приоритет между продуктами и проектами.
2. Честный ETA с учётом ёмкости и очередей нескольких команд.
3. Прозрачность кросс-командных инициатив и bottleneck.
4. Быстрый what-if по FTE/ёмкости и шкале майок без смены трекера.
5. Доступ по ссылке для команды без установки ПО.

### Out of scope (v1)

Auth/RBAC, аудит изменений, интеграция Jira/Linear, удаление команд, native mobile, realtime multiplayer, мультитенантность, approval workflow приоритета, импорт/экспорт JSON из шапки.

## 2. Акторы

| ID | Актор | Цель |
|---|---|---|
| A1 | Product / Portfolio Owner | Единый приоритет и ETA по всему портфелю |
| A2 | Team Lead | Очередь своей команды и загрузка ёмкости |
| A3 | Stakeholder / коллега | Просмотр плана и экспорт PDF по ссылке |
| A4 | Администратор развёртывания | Опубликовать приложение и общую БД |

## 3. Use cases

### UC-01 — Просмотреть единый портфель

- **Акторы:** A1, A2, A3  
- **Триггер:** открытие приложения / вкладка «Портфель» / клик по логотипу «VI Planer»  
- **Предусловия:** загружено состояние (облако / API / localStorage / демо)  
- **Основной сценарий:**
  1. Система показывает метрики: активные инициативы, горизонт, команды под риском, старт планирования.
  2. Система показывает таблицу инициатив (тип, команды с майками, статус, WSJF, оценка, ETA).
  3. Пользователь может раскрыть «Адженда» с легендой колонок.
- **Альтернатива:** нет данных → заполнение демо-seed.  
- **Постусловие:** пользователь видит актуальный портфель.

### UC-02 — Отфильтровать и отсортировать портфель

- **Акторы:** A1, A2  
- **Триггер:** фильтр / клик по заголовку колонки  
- **Сценарий:** поиск, тип, команда, статус; сортировка по Приоритет / WSJF / Оценка / ETA; сброс фильтров.  
- **Постусловие:** таблица отражает выбранный срез.

### UC-03 — Создать инициативу

- **Актор:** A1  
- **Триггер:** «+ Инициатива»  
- **Сценарий:** заполнение полей (название, тип, бэклог, статус, владелец, WSJF, приоритет, заметки); назначение ≥1 команды с майкой (S/M/L) и стартом (понедельник); live WSJF/ETA; сохранение.  
- **Альтернативы:** нет команд → alert; Отмена/Закрыть → без сохранения.  
- **Постусловие:** инициатива в портфеле, приоритеты уникальны 1…n.

### UC-04 — Редактировать / удалить инициативу

- **Актор:** A1  
- **Триггер:** клик по строке  
- **Сценарий:** изменение полей и команд → Сохранить.  
- **Альтернатива:** Удалить (без доп. confirm).  
- **Постусловие:** портфель и расписание пересчитаны.

### UC-05 — Изменить сквозной приоритет

- **Актор:** A1  
- **Триггер:** ввод ранга / drag ⋮⋮  
- **Предусловие drag:** сортировка по «Приоритет»  
- **Сценарий:** новый ранг; при конфликте — confirm; переиндексация 1…n; drag в видимом списке.  
- **Альтернативы:** drag при другой сортировке недоступен; отказ в confirm.  
- **Постусловие:** очереди и Gantt следуют новому порядку.

### UC-06 — Управлять командами, майками и ёмкостью

- **Акторы:** A2, A1  
- **Триггер:** вкладка «Настройки»  
- **Сценарий:** название и capacity 1–8 (шаг 0.5) у команд; создание команды; диапазоны недель для майок S/M/L; пересчёт ETA/риска.  
- **Альтернатива:** удаление команды — вне scope v1.

### UC-07 — Просмотреть очередь команд

- **Акторы:** A2, A1  
- **Триггер:** «Очередь команд»  
- **Сценарий:** единый вид по всем командам: очередь по приоритету, план/сдвиг, даты, «может взять с…» / причина, утилизация 8 нед.; тогглы «Показать загрузку команд» и «Автоматически сдвигать по ёмкости».  
- **Постусловие:** пользователь видит загрузку и слоты команд.

### UC-08 — Просмотреть сроки (Gantt)

- **Акторы:** A1, A3  
- **Триггер:** «Gantt/Сроки»  
- **Сценарий:** полоски по командам, bottleneck, зависимости очереди (в авто-режиме); горизонт 4–52 нед.; опционально полосы загрузки команд по неделям.  
- **Альтернатива:** статус «Готово» исключается из расписания.

### UC-09 — Сохранить и синхронизировать данные

- **Акторы:** A1, A2  
- **Триггер:** любое изменение  
- **Сценарий:** localStorage сразу; debounce → Supabase и/или PUT `/api/state`; индикатор синхронизации в шапке.  
- **Альтернатива:** API/облако недоступны → локальный fallback.

### UC-10 — Скачать PDF текущей вкладки

- **Акторы:** A1, A3  
- **Триггер:** «Экспорт PDF» в шапке  
- **Сценарий:** цветной landscape A4 PDF метрик + активной вкладки (Портфель / Gantt / Очередь / Настройки); библиотеки html2canvas и jspdf бандлятся с приложением (без CDN).  
- **Альтернатива:** ошибка захвата → alert.

### UC-11 — «Сбросить демо» (шутка без очистки)

- **Актор:** A1  
- **Триггер:** кнопка «Сбросить демо» в Настройках  
- **Сценарий:** трёхшаговый диалог («Сбросить к демо?» → «Подумай еще раз…» → «Спасибо тебе»); данные портфеля **не** очищаются и **не** заменяются seed.  
- **Альтернатива:** Нет / Escape / клик снаружи на любом шаге.

### UC-12 — Открыть приложение по публичной ссылке

- **Акторы:** A3, A4  
- **Сценарий:** GitHub Pages (+ Supabase shared) / Railway·Render·VPS с Python FastAPI или Node Express / LAN.  
- **Альтернатива:** Pages без Supabase → данные per-browser (`VITE_LOCAL_STORAGE_ONLY`).

### UC-13 — Вернуться на главную (Портфель)

- **Акторы:** A1, A2, A3  
- **Триггер:** клик по бренду «VI Planer» в шапке  
- **Сценарий:** активная вкладка переключается на «Портфель».

## 6. Модель данных (v1)

### AppState
`version` (3), `startDate`, `teams[]`, `items[]`, `sizeRanges` (S/M/L → min/max недель)

### Team
`id`, `name`, `capacityPw`, `color`

### WorkItem
`id`, `title`, `type` (product|project), `backlog`, `status`, `owner`, `assignments[]`, `businessValue`, `timeCriticality`, `riskReduction`, `jobSize`, `notes?`, `manualRank`

### TeamAssignment
`teamId`, `size` (S|M|L), `workStartDate` (понедельник)  
Effort в чел·нед = midpoint диапазона майки из `sizeRanges`.

### Расчётные (не persist)
`ScheduledSlice`, `ItemSchedule`, `TeamLoadWeek` — очереди, ETA, bottleneck, загрузка по неделям.

## 7. Критерии приёмки (smoke)

1. Создать инициативу на 2 команды с майками.  
2. Изменить приоритет drag.  
3. Включить авто-сдвиг по ёмкости и увидеть сдвиг ETA на Gantt.  
4. Экспорт PDF с каждой вкладки (без зависимости от CDN).  
5. Перезагрузить страницу — данные сохранились (Pages+Supabase или API).  
6. Клик по «VI Planer» → Портфель.  
7. «Сбросить демо» проходит 3 шага и **не** очищает данные.  
8. Скачать файл требований из нижней кнопки.
