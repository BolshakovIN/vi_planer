Очереди команд: новый проект / функциональность

Use-case VI Planer: вставка в портфель → сдвигать ли очереди → полный или частичный сдвиг → при частичном — выбор оптимизации ёмкости → пересчёт дат → оповещение.

Оповещение — процесс / UX-intent (есть журнал изменений; авто-рассылка не обязательна). Выбор A/B в случае 3 — intent; в SPA режим задаётся глобально кнопками на Gantt / «Очередь команд».

Три случая

1. Без сдвига

  • Вставка в слот / хвост без пересчёта чужих дат
  • Режим «Как задано» (manual)
  • Старты из карточек; перегрузки видны

2. Полный сдвиг

  • Затронуты все команды функциональности
  • Полный пересчёт затронутых очередей
  • Ниже по приоритету сдвигаются; ETA = max по трекам

3. Частичный сдвиг

  • Сдвиг только в части команд
  • Нужно выбрать тип оптимизации ёмкости (A или B)
  • Пересчёт только затронутых очередей

Два типа оптимизации (случай 3)

Тип Подпись в UI Режим Суть
A Последовательная утилизация ресурса teamQueue FS-очередь по приоритету внутри команды; следующая работа ждёт конца предыдущей
B Максимальная утилизация ресурса maxUtilization Все команды одной функциональности стартуют вместе; дата завершения = max по трекам
